# Current limits and evidence

This is an implementation checkout, not a released or device-accepted build. Local checks include host unit/integration tests, Flutter tests, PWA static build, and an Android debug APK build. Flutter analysis reports no errors, but still exits nonzero on 16 legacy warnings and informational lints. On an Android 15 emulator, pairing and auto-reconnect worked; Agents was the default screen; a real PTY showed its initial prompt and accepted `pwd`; Files navigated to `/tmp`; DownloadManager saved a test file in public `Downloads/NexusLink`; the editor saved a change and blocked a conflicting PC edit; the foreground live service displayed its notification and optional bubble. The Files path dialog initially crashed during its close transition; it was fixed and retested on the emulator, with a widget regression test added. No physical Android phone, screen-off transfer, Tailscale handoff, provider run, or release upgrade has been exercised. Streaming quality was not repaired; it remains experimental and off by default.

Directory rename and recursive deletion remain unavailable in the new Files view. Git inspection is read-only. The editor has no language server, extensions, or debugger. File saves detect observed revision changes and replace atomically, but cannot lock unrelated PC applications in the final filesystem race window. Shells end on host restart. Operation-ID deduplication is per running host process. The Android background monitor is opt-in and subject to Android notification, foreground-service, and overlay permissions as well as manufacturer power restrictions. Its actual state should be verified on the target phone.

Paired device credentials remain bound to the saved host address. Switching between a Tailscale IP and MagicDNS name requires pairing again. A host ID supplied before authentication is not sufficient proof that a different address belongs to the same PC; seamless migration would require a verified host key.

Release signing identity has not been reconciled with any previously distributed APK. A debug build does not establish upgrade compatibility, and no new APK has been published. Release builds now require an explicit key; follow [Android release identity](ANDROID-RELEASE.md) before selecting it.
